# ICODA verified baseline and gap analysis

Date: 2026-09-11 (updated through iteration 60)

## Scope and status meanings

This analysis uses the repository-root `README.md` and `CLAUDE.md`, plus the ICODA documents to which the root
README delegates the design: `icoda/EVOLUTION.md`, `icoda/ICODA_PLAN.md`, and `icoda/README.md`. There was no
`docs/` directory before this report and no `AGENTS.md` in the repository. The Markdown files under `ai-loop/`
describe the separate AI-Loop application and are not ICODA plans or specifications.

- **DONE**: the planned capability is implemented and has direct code/test evidence.
- **PARTIAL**: a useful implementation exists, but one or more behaviors promised by the design are absent or not
  currently verifiable.
- **MISSING**: no implementation of the planned capability was found.

## Verified baseline

### Test and visual evidence

- The loop's Python 3.12 interpreter initially contained only pip and Redis, so its `python -m pytest -q` could not
  start because pytest was not installed. An earlier run using a temporary environment found 13 failures,
  595 passes, and 13 skips. Twelve failures came from running the two otherwise independent applications in one
  pytest process (working-directory assumptions and incompatible Tk test setup); one was an ICODA host-dependent
  libc++ lookup failure.
- After the test-isolation setup in `conftest.py:isolate_application` and the clang-only correction in
  `icoda/icoda_core/analysis.py:libcxx_arguments`, the repository-root command is green. Installing both
  applications with their `dev` extras into the loop's existing `.gui-venv` makes its own interpreter run the
  suite unaided. Narrowing Tk isolation to ICODA instead of deleting `DISPLAY` globally produces the final result:
  **668 passed, 13 skipped**. The application counts are **507 passed, 1 skipped** for AI-Loop and
  **161 passed, 12 skipped** for ICODA. With the former unconditional `os.environ.pop("DISPLAY")`, AI-Loop had
  **497 passed, 11 skipped**; it incorrectly converted ten passing real-display tests into skips. The ICODA skips
  are the module/sample and end-to-end step tests that require `clang++`, which is not installed on this host.
- A real-Tk visual acceptance run against a temporary, built 13-file CMake project passed
  `icoda/tests/gui_acceptance.py:main`. It captured and validated six 1200x760 screenshots: fitted and zoomed File
  View, fitted and zoomed Call View, proposal Delta, and proposal Source diff. The opened model was fresh and
  contained 16 entities, 3 relations, and 4 clusters. Evidence is under `/tmp/icoda-gui-smoke-screenshots/`.
- Iteration 45 makes both project-owned verification entry points green on this Linux host. The harness selects the
  installed module-capable Clang through `icoda_core/steps.py:build_environment`, builds the sample before coverage
  tests consume its compile database, analyses a fresh model, and validates all 32 real-Tk screenshots. The unchanged
  branch threshold is 85%; the measured tested-branch coverage is **90.00%**. The repository-root suite is
  **814 passed, 4 skipped**; no tests were added, and the nine-pass increase/nine-skip decrease from iteration 44 is
  the formerly skipped module/sample analysis set now executing against the Clang-built project.
- Iteration 46 qualifies legacy migration and interrupted-run recovery without changing the 90.00% coverage result.
  The repository-root suite is **816 passed, 4 skipped**, exactly the two new durability tests above iteration 45.
  Migration needs no production change; truncated workflow state is explicitly refused, and an unfinished proposal
  worktree is reported and preserved. Large-project performance (7C2) and platform qualification (7B) remain open.
- Iteration 47 closes the two developer-visible recovery holes left by that qualification. The App routes an
  unreadable-state `ProjectStateError` through its existing status/dialog reporting path instead of allowing a Tk
  callback traceback; a valid state with a leftover proposal worktree reopens with an explicit preservation notice.
  `ProjectStore.ensure()` is pinned byte-for-byte against rewriting an existing unreadable state. The root suite is
  **819 passed, 4 skipped**, and exercised-branch coverage is **90.08%** against the unchanged 85% threshold.
- Iteration 48 pins the successful-open half of that recovery path: a project whose persisted workflow phase is
  `implementation` still shows `Phase implementation` after `App.open_project` and `_poll`. The test was green-first
  because `App.show` already loads/normalizes state through `implementation_queue.ensure_state` and calls
  `StepPanel.set_phase`; no production code changed. The root suite is **820 passed, 4 skipped**, exercised-branch
  coverage remains **90.08%**, and the real-Tk run still validates exactly 32 screenshots.
- Iteration 49 closes gap 7C2's measurement obligation with a deterministic 50/300-module Python harness and retained
  wall-clock/tracemalloc evidence. The 300-module model has 3,600 entities and 4,198 edges; its seven measured stages
  total 89.157702 seconds, so current large-project open latency is not acceptable for an interactive overview.
  Four named performance defects remain open: `python_analysis.parse_project`, `views.layout_file_view`,
  `coverage_index.build_index`, and `expansion.derive` exceed the declared 1.50x large/small microseconds-per-entity
  signal. This qualification iteration makes no production speed change.

  79.211 cumulative seconds to 914,400 `DerivedModel.callers` invocations; `build_index` now constructs one
  recorded-identifier reachability index per call instead of walking callers and rescanning all edges for every

  per-entity scaling instead of 34.960x; large summed latency is 4.389153s and meets the harness's 10.0s interactive
  interpretation. The three untouched iteration-49 defects remain open.
- Iteration 51 closes gap 7B by recording the versioned three-platform status in `icoda/docs/RELEASE_MATRIX.md` without
  overstating execution: Linux is the only qualified platform; Windows and macOS are unqualified and unmeasured
  because no such hosts exist in this environment. Two host-independent tests prove `steps.build_environment`
  selects its macOS and Windows fallback branches without entering Linux executable-path discovery. They do not
  qualify either operating system. Gap 7C2 bookkeeping now marks `coverage_index.build_index` closed and retains
  the three remaining material-growth signals as open but not blocking because the large-project summed overview
